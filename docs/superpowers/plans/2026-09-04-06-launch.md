# RAGBench Launch Implementation Plan (Plan 6 of 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship RAGBench as a launchable OSS project: pay down every ledgered debt, give the whole app a real design system (the current UI is unstyled house-pattern HTML), stand up CI + E2E, produce a prod deployment story, and write the README/LICENSE a stranger needs to run it keyless in five minutes.

**Architecture:** Five tasks: (1) a debt wave over worker/db/api touching no UI; (2) the full UI design pass introducing a shared design module and restyling every page; (3) Playwright E2E in demo mode + GitHub Actions CI; (4) prod Dockerfile, compose app/worker services, and a stuck-run reconciliation job; (5) README, LICENSE, quickstart env docs. Tasks 1 and 2 are independent; 3 depends on 2 (selectors), 4 and 5 close the launch.

**Tech Stack:** existing monorepo (Next 16, pg-boss 12, Drizzle, vitest) + Playwright + GitHub Actions.

**Spec:** docs/superpowers/specs/2026-09-03-ragbench-design.md (§8 visual direction, §10 mock/demo mode, §11 testing, §12 deferred). Ledgered rulings in .superpowers/sdd/2026-09-03-04-eval-engine/progress.md and .superpowers/sdd/2026-09-03-05-attribution/progress.md bind where they touch this plan.

## Global Constraints

- TypeScript strict, no `any`; Postgres host port 5433 (5432 is another project's — never touch); pnpm; conventional commits; repo-local identity, no --author, no Co-Authored-By trailer.
- Visual direction (spec §8 + design-taste): cool neutral palette, single sans-serif stack, color reserved for STATE (hit/miss/verdict/status). Dashboard aesthetic, not decorative. No warm-paper/serif/terracotta look.
- Mock/demo mode stays fully keyless end-to-end; nothing in this plan may add a required key.
- Full `pnpm test` + `pnpm typecheck` green before every commit. Kill any stray `tsx src/main.ts` worker processes before test runs (they steal pg-boss jobs from the suite).

# RAGBench Eval Engine Implementation Plan (Plan 4 of 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Side-by-side config evaluation: create rag configs, run a test set against 2–3 of them, and get hit@k / MRR / faithfulness / correctness per config with a per-question drill-down — plus the accumulated design-debt items (metering contract, embed-model persistence, embed-failure visibility, remaining indexes).

**Architecture:** A `start-run` worker job fans out one `evaluate-question` job per (config × active question) with singleton keys `${runId}:${configId}:${questionId}` (exclusive-policy requirement). Each job: embed the question, KNN via pgvector cosine (`<=>`, PINNED — Gemini-truncated embeddings are not re-normalized, so cosine is the only correct operator), hit = retrieved chunk's doc+span overlaps the gold span, reciprocal rank from the first hit; full mode additionally answers from retrieved chunks (answerModel) and judges (judgeModel) with 0–1 faithfulness/correctness; results upserted idempotently; run progress counted in SQL; run flips `done` when all jobs account. Aggregates computed on read (spec §6). Mock models keep the whole loop keyless (deterministic mockJudge).

**Spec:** `docs/superpowers/specs/2026-09-03-ragbench-design.md` (§6 fully; retrieval-only mode included). Judge pinned per run (spec judgment call 1).

## Global Constraints

- Postgres 5433; singleton keys as above; handlers idempotent (retry may re-run).
- Providers only via factories with `makeUsageReporter`; purposes: `"answer"`, `"judge"`, `"query-embed"`. Keyless CI (mock models end-to-end).
- Cosine distance operator `<=>` ONLY (comment why at the query site).
- Failure classes (established pattern): non-retryable ProviderError on a question job → `question_results` row status `failed` with error, run continues; retryable → propagate for pg-boss retry; run-level integrity errors (missing entities) → no-op or run `failed`.
- Org-scoping via requireProject / ownership chains on every route; model names validated via `Object.hasOwn` lookups.
- TypeScript strict; conventional commits, no trailer.

### Task 2: Metrics + judge prompts (core, pure)

**Files:**
- Create: `packages/core/src/metrics.ts`, `packages/core/src/judge.ts`
- Modify: `packages/core/src/index.ts`
- Test: `packages/core/test/metrics.test.ts`, `packages/core/test/judge.test.ts`

**Interfaces:**
- metrics.ts: `type Span = { start: number; end: number }`; `spansOverlap(a: Span, b: Span): boolean` (half-open, true iff intersection non-empty); `evaluateRetrieval(retrieved: Array<{ documentId: string; span: Span }>, gold: { documentId: string; span: Span }): { hit: boolean; reciprocalRank: number }` — first index i (0-based) where documentId matches AND spans overlap → hit true, rr = 1/(i+1); none → hit false, rr 0.
- judge.ts: `buildAnswerPrompt(question: string, chunks: string[]): string` (answer ONLY from the excerpts; say "I cannot answer from the provided context" when absent); `buildJudgePrompt(question, goldAnswer, answer, chunks: string[]): string` → strict JSON `{"faithfulness": 0..1, "correctness": 0..1, "reason": "..."}`; `parseJudgeJson(raw): { faithfulness: number; correctness: number; reason: string } | null` (clamp to [0,1], null on garbage); `mockAnswer(question, chunks)` deterministic: return the first chunk's first sentence prefixed "Based on the context: "; `mockJudge(goldAnswer, answer): {faithfulness, correctness, reason}` deterministic: correctness = 1 if `normalizeWs(answer)` contains the first 5 words of `normalizeWs(goldAnswer)` else 0; faithfulness mirrors correctness; reason fixed string.
- [ ] Steps: TDD (overlap edges: touching spans NOT overlapping [half-open], containment, cross-doc same-span no-hit, rr math; judge parse clamp/garbage; mock determinism) → implement → green → commit `feat: retrieval metrics and judge prompts with deterministic mocks`.

### Task 3: evaluate-question + start-run jobs (worker)

**Files:**
- Create: `apps/worker/src/handlers/evaluate-question.ts`, `apps/worker/src/handlers/start-run.ts`, `apps/worker/src/retrieve.ts`
- Modify: `apps/worker/src/main.ts`
- Test: `apps/worker/test/eval.test.ts`

**Interfaces:**
- retrieve.ts: `retrieveTopK(db, { chunkSetId, model, queryEmbedding, k }): Promise<Array<{ chunkId, documentId, startOffset, endOffset, text, score }>>` — raw SQL via drizzle `sql` template: join chunks↔chunk_embeddings, filter set+model, `ORDER BY embedding <=> ${vector} LIMIT k`; score = 1 - distance. Comment PINNING cosine (`<=>`) with the Gemini-truncation rationale.
- start-run.ts: `startRunHandler: JobHandler<{ runId: string; organizationId: string }>` — load run (missing/`done`/`cancelled` → no-op); load configs (eval_run_configs) + active questions; validate each config's (chunkSet × embeddingModel) has ≥1 embedding row → else run status `failed`, error naming the config (terminal, no throw); set `totalJobs = configs × questions`, status `running`; enqueue every evaluate-question job (singleton keys). Idempotent: re-run re-enqueues (exclusive keys dedupe in-flight; completed jobs' rows exist so re-executed jobs no-op via upsert).
- evaluate-question.ts: `evaluateQuestionHandler: JobHandler<{ runId, configId, questionId, organizationId }>`:
  1. Existing non-failed result row → done (idempotent short-circuit, but still run the progress accounting step 7 idempotently — see below).
  2. Load run (status `cancelled`/`failed` → no-op), config, question (deleted → count as completed without result? Simpler: treat deleted question rows as still evaluable — start-run snapshots ACTIVE questions at fan-out; a question deleted mid-run just evaluates anyway; acceptable v1, note in code).
  3. Query embed via `makeEmbedder(config.embeddingModel, reporter)` (purpose "query-embed"), `retrieveTopK`.
  4. `evaluateRetrieval` against gold (documentId + goldStart/goldEnd).
  5. Full mode: answer via `run.answerModel ?? run.judgeModel` — mock-llm → `mockAnswer`; judge via `run.judgeModel` — mock-llm → `mockJudge`; else prompts + parse (null parse → judge fields null, judgeRaw records raw).
  6. Upsert question_results (onConflictDoNothing then update-if-was-failed; simplest: delete failed row then insert, in a txn) with retrieved (chunkId/rank/score), hit, rr, answer, faithfulness, correctness, judgeRaw, status done. Non-retryable ProviderError → row status `failed` + error (no throw); retryable → throw.
  7. Progress: `completedJobs = count(question_results rows for run)` recomputed in SQL (idempotent, no drift); when == totalJobs → run status `done`.
- [ ] Steps: TDD keyless with mock models end-to-end (seed corpus + chunk set + mock embeddings via real handlers; test-set questions seeded directly with known spans): (a) retrieval-only run completes: results rows per config×question, hit true for a question whose gold span IS in a chunk, run status done, totalJobs/completedJobs equal; (b) full mode adds answer + judge fields (deterministic mockJudge asserted); (c) config with zero embeddings → run failed with config named; (d) job retry idempotency (run handler twice → single row); (e) rank math spot-check (gold in second-nearest chunk → rr 0.5) — craft with hashEmbed-friendly texts. → implement → green + full suite → commit `feat: evaluate-question fan-out with span-overlap metrics and judged answers`.

- run detail GET `/api/runs/:runId` (org-scoped via run→project): `{ run, configs: [{ config, aggregates: { questions, evaluated, failed, hitRate, mrr, avgFaithfulness, avgCorrectness } }], grid: [{ questionId, question, perConfig: { [configId]: { hit, reciprocalRank, status } } }] }` — aggregates computed on read via SQL avg/count.
